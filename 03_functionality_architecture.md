# 1.3 Функционал и архитектура

## 1. Функциональные требования

### 1.1 Интерфейс пациента («Пульс», адаптивный веб, mobile-first)

| ID | Функция | Описание | Приоритет |
|---|---|---|---|
| P-1 | Регистрация и вход | Создание профиля пациента (с указанием адреса электронной почты для уведомлений), вход в приложение | MVP |
| P-2 | Напоминания о лекарствах | Расписание приёма (препарат, доза, время), push-уведомления в браузере и дублирующее письмо на электронную почту, отметка «принял» | MVP |
| P-3 | ИИ-помощник | Чат с помощником на базе YandexGPT: справочные ответы на мед. вопросы, не диагностика | MVP |
| P-4 | Голосовые напоминания | Текст напоминания озвучивается нейросетевым синтезом речи (Yandex SpeechKit) для пожилых пользователей; аудио проигрывается при переходе по ссылке из уведомления | MVP |
| P-5 | Кнопка вызова помощи | Быстрое действие: звонок на номер экстренной помощи/врача | MVP / итог |
| P-6 | Карта до ближайшего ФАП | Показ ближайшего ФАП и маршрут до него | MVP / итог |
| P-7 | Чат с врачом | Текстовые сообщения «пациент ↔ врач» | Итоговая версия (до 1 декабря) |
| P-8 | Крупный интерфейс | Крупные шрифты и кнопки, простая навигация (для пожилых), удобная работа на экране телефона | сквозное |

### 1.2 Кабинет врача

| ID | Функция | Описание | Приоритет |
|---|---|---|---|
| D-1 | Вход врача | Авторизация сотрудника | Итоговая версия |
| D-2 | Список пациентов | Просмотр пациентов, закреплённых за врачом | Итоговая версия |
| D-3 | Просмотр режима приёма лекарств | Расписание и отметки пациента | Итоговая версия |
| D-4 | Чат с пациентами | Ответы на сообщения пациентов | Итоговая версия |

## 2. Нефункциональные требования

| Категория | Требование |
|---|---|
| Удобство | Простой интерфейс, крупные элементы, голосовое сопровождение |
| Адаптивность | Интерфейс корректно отображается и работает на экране телефона (от 360 px) и на компьютере |
| Надёжность | Рассылка напоминаний выполняется отдельным сервисом уведомлений со своим планировщиком и не зависит от доступности backend |
| Уведомления | Пациент разрешает push-уведомления в браузере и указывает адрес электронной почты; если push недоступен или отключён, напоминание приходит письмом |
| Безопасность | Хранение и передача данных по защищённому каналу (HTTPS), разграничение прав пациент/врач, минимум персональных данных |
| Соответствие закону | Учёт требований 152-ФЗ о персональных данных |
| Производительность | Ответ ИИ-помощника за приемлемое время, чат в режиме, близком к реальному |
| Ограничение ИИ | Ответы помощника сопровождаются предупреждением, что это справка, а не диагноз или назначение |

## 3. Роли пользователей

- **Пациент** — работает через веб-приложение с телефона.
- **Врач** — работает через кабинет врача (веб, чаще с компьютера).
- **Администратор** — создаёт учётные записи врачей, закрепляет пациентов за врачами, ведёт справочники (ФАП, препараты).

## 4. Архитектура системы (верхний уровень)

Схема в файле `pulse_architecture.excalidraw`.

### 4.1 Компоненты

**Клиент**

1. **Веб-приложение «Пульс»** — единый адаптивный клиент с Service Worker для приёма push-уведомлений. Интерфейс пациента (напоминания, ИИ-чат, SOS, карта до ФАП, чат с врачом) рассчитан на телефон; кабинет врача (список пациентов, расписания приёма, чат) — на компьютер. Технология: HTML-шаблоны Jinja2 и HTMX (обновление частей страницы и чат по WebSocket без перезагрузки); небольшие вставки JavaScript для Service Worker и Яндекс Карт.

**Собственные серверные сервисы**

2. **Backend** — отдача страниц клиента (шаблоны Jinja2), REST API и WebSocket (чат), авторизация, роли, бизнес-логика. Технология: Python / FastAPI.
3. **База данных** — пользователи, расписания лекарств, сообщения, справочник ФАП. Технология: PostgreSQL.
4. **Сервис ИИ-помощника** — серверная прослойка над API YandexGPT (ключи хранятся на сервере, не в клиенте).
5. **Сервис уведомлений** — отдельный облачный сервис, не входящий в backend. Имеет собственный планировщик и собственное хранилище расписаний. Получает от backend расписания напоминаний, в нужное время сам рассылает напоминания: push-уведомлением через push-провайдера и дублирующим письмом через почтовый сервис.

**Внешние сервисы**

6. **Нейросетевой синтез речи** — Yandex SpeechKit, озвучивание текста напоминаний.
7. **YandexGPT API** — генерация ответов ИИ-помощника.
8. **Картографический сервис** — Яндекс Карты: карта и маршрут до ФАП.
9. **Push-провайдер** — внешняя доставка Web Push на устройство пациента.
10. **Почтовый сервис (SMTP-провайдер)** — отправка писем с напоминаниями (дублирующий и резервный канал).

### 4.2 Взаимодействия

- Веб-приложение ↔ Backend: HTTPS/REST, WebSocket для чата (интерфейсы пациента и врача).
- Backend → Сервис ИИ-помощника → YandexGPT API: запросы от имени сервера.
- Backend ↔ БД: хранение данных.
- Backend → Сервис уведомлений: передача и обновление расписаний напоминаний (API). Обратной зависимости нет: сервис уведомлений работает независимо от backend.
- Сервис уведомлений → Push-провайдер → Веб-приложение (Service Worker): доставка напоминаний и уведомлений о новых сообщениях.
- Сервис уведомлений → Почтовый сервис → Почта пациента: дублирующее письмо с напоминанием; ссылка в письме открывает веб-приложение.
- Backend → Синтез речи (SpeechKit): формирование аудио по тексту напоминания; результат кэшируется и отдаётся клиенту через backend.
- Веб-приложение ↔ Картографический сервис: отображение карты и маршрута.

### 4.3 Принципы

- Единый клиент и единый backend для пациента и врача, чтобы не дублировать логику.
- Напоминания планирует и рассылает отдельный сервис уведомлений со своим планировщиком; backend только передаёт ему расписания.
- Секреты и ключи внешних API хранятся только на сервере.
- Разделение прав доступа: пациент видит только свои данные, врач — только своих пациентов.

## 5. Основные сценарии (use cases)

1. **Пациент настраивает напоминание** → добавляет препарат и время → backend передаёт расписание сервису уведомлений → в нужное время приходит push-уведомление в браузер и дублирующее письмо → пациент открывает приложение и отмечает «принял».
2. **Пациент спрашивает ИИ-помощника** → запрос на backend → YandexGPT → ответ с оговоркой «не диагноз».
3. **Голосовое напоминание** → сервис уведомлений отправляет push и дублирующее письмо → пациент открывает уведомление или ссылку из письма → приложение получает аудио, синтезированное SpeechKit, и проигрывает его.
4. **Вызов помощи** → пациент нажимает SOS → набор номера экстренной помощи, при необходимости показ ближайшего ФАП.
5. **Переписка с врачом** → пациент пишет → врач видит сообщение в кабинете → отвечает → пациент получает уведомление.
