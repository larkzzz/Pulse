# 1.3 Функционал и архитектура

> Раздел согласуем с преподавателем. Пункты, помеченные **(предложение)**, — мои черновые решения, их можно обсудить.

## 1. Функциональные требования

### 1.1 Мобильное приложение пациента («Пульс»)

| ID | Функция | Описание | Приоритет |
|---|---|---|---|
| P-1 | Регистрация и вход | Создание профиля пациента, вход в приложение | MVP |
| P-2 | Напоминания о лекарствах | Расписание приёма (препарат, доза, время), пуш-уведомления, отметка «принял» | MVP |
| P-3 | ИИ-помощник | Чат с помощником на базе YandexGPT: справочные ответы на мед. вопросы, не диагностика | MVP |
| P-4 | Голосовые напоминания | ИИ-помощник озвучивает напоминания для пожилых пользователей | MVP |
| P-5 | Кнопка вызова помощи | Быстрое действие: звонок на номер экстренной помощи/врача | MVP / итог |
| P-6 | Карта до ближайшего ФАП | Показ ближайшего ФАП и маршрут до него | MVP / итог |
| P-7 | Чат с врачом | Текстовые сообщения «пациент ↔ врач» | Итоговая версия (до 1 декабря) |
| P-8 | Крупный интерфейс | Крупные шрифты и кнопки, простая навигация (для пожилых) | сквозное |

### 1.2 Веб-кабинет врача

| ID | Функция | Описание | Приоритет |
|---|---|---|---|
| D-1 | Вход врача | Авторизация сотрудника | Итоговая версия |
| D-2 | Список пациентов | Просмотр пациентов, закреплённых за врачом | Итоговая версия |
| D-3 | Просмотр режима приёма лекарств | Расписание и отметки пациента | Итоговая версия |
| D-4 | Чат с пациентами | Ответы на сообщения из мобильного приложения | Итоговая версия |

### 1.3 Вне рамок (развитие)

- Видеосвязь с врачом.
- Интеграция с датчиками/носимыми устройствами.
- Интеграция с ЕГИСЗ.
- Кабинет родственника.

## 2. Нефункциональные требования **(предложение)**

| Категория | Требование |
|---|---|
| Удобство | Простой интерфейс, крупные элементы, голосовое сопровождение |
| Надёжность | Напоминания приходят вовремя, в том числе при слабом интернете (локальные уведомления) |
| Безопасность | Хранение и передача данных по защищённому каналу (HTTPS), разграничение прав пациент/врач, минимум персональных данных |
| Соответствие закону | Учёт требований 152-ФЗ о персональных данных |
| Производительность | Ответ ИИ-помощника за приемлемое время, чат в режиме близком к реальному |
| Ограничение ИИ | Ответы помощника сопровождаются предупреждением, что это справка, а не диагноз или назначение |

## 3. Роли пользователей

- **Пациент** — работает через мобильное приложение.
- **Врач** — работает через веб-кабинет.
- *(Возможно)* **Администратор** — управление врачами и справочниками.

## 4. Архитектура системы (верхний уровень)

Схема в файле `pulse_architecture.excalidraw`.

### 4.1 Компоненты

1. **Мобильное приложение (Kotlin)** — клиент пациента: напоминания, ИИ-чат, SOS, карта, чат с врачом.
2. **Веб-кабинет врача** — отдельный сайт: список пациентов, расписания, чат.
3. **Backend (REST API + WebSocket для чата)** — единая серверная часть, бизнес-логика, авторизация. Стек **(предложение: Kotlin/Ktor или Spring Boot, чтобы не расходиться с мобильным стеком)**.
4. **База данных** — пользователи, расписания лекарств, сообщения, справочник ФАП **(предложение: PostgreSQL)**.
5. **Сервис ИИ-помощника** — серверный слой-прослойка над API YandexGPT (ключи хранятся на сервере, не в приложении).
6. **Сервис синтеза речи** — озвучка напоминаний (**предложение: Yandex SpeechKit**)
7. **Картографический сервис** — карта и маршрут до ФАП (**предложение: Яндекс Карты**).
8. **Сервис push-уведомлений** — доставка напоминаний и уведомлений о новых сообщениях.

### 4.2 Взаимодействия

- Мобильное приложение ↔ Backend: HTTPS/REST, WebSocket для чата.
- Веб-кабинет ↔ Backend: HTTPS/REST, WebSocket для чата.
- Backend ↔ YandexGPT: запросы от имени сервера.
- Backend ↔ БД: хранение данных.
- Мобильное приложение ↔ Картографический сервис: отображение карты и маршрута.

### 4.3 Принципы

- Единый backend для обоих клиентов, чтобы не дублировать логику.
- Напоминания планируются локально на устройстве, чтобы работали без сети.
- Секреты и ключи внешних API только на сервере.
- Разделение прав доступа: пациент видит только свои данные, врач — только своих пациентов.

## 5. Основные сценарии (use cases)

1. **Пациент настраивает напоминание** → добавляет препарат, время → приложение уведомляет → пациент отмечает «принял».
2. **Пациент спрашивает ИИ-помощника** → запрос на backend → YandexGPT → ответ с оговоркой «не диагноз».
3. **Голосовое напоминание** → в нужное время приложение озвучивает напоминание.
4. **Вызов помощи** → пациент нажимает SOS → звонок/набор номера, при необходимости показ ближайшего ФАП.
5. **Переписка с врачом** → пациент пишет → врач видит сообщение в кабинете → отвечает → пациент получает уведомление.
